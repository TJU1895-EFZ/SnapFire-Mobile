# SnapFire Mobile — 产品需求文档（PRD）

- 文档版本：v1.0
- 日期：2026-10-24
- 状态：草案
- 产品名称：SnapFire Mobile
- 运行平台：手机浏览器（Chrome / Edge / Safari）
- 项目关系：SnapFire 桌面版 v1.0.0 的移动端分支，独立仓库

---

## 1. 产品目标与使用场景

### 1.1 产品定位

SnapFire Mobile 是 SnapFire 桌面版的**手机浏览器客户端**。它不运行房间服务器，仅作为**纯客户端**通过 WebSocket 加入桌面版房主创建的局域网房间，参与 3V3 巷战。

### 1.2 核心体验

1. 玩家用手机代替笔记本，摄像头对准对手，屏幕当作"瞄准镜"。
2. 手机屏幕全屏显示摄像头画面，叠加 3D 手臂/枪械、准心、HUD。
3. 玩家用手指点击屏幕右下角的**虚拟扳机**开火，用手指在屏幕左侧**滑动选择目标**。
4. 手机本地运行 AI 人体/人脸/衣着识别，判断准心对准的是谁、属于哪队。
5. 命中后，房主电脑的服务器实时扣血；血量归零后进入阵亡和复活流程。
6. 一局结束后在手机上看比分、个人战绩。

### 1.3 目标使用场景

- 场地：室内，如办公室、教室、活动室、走廊等，允许玩家小幅移动。
- 人数：一房最多 6 人（桌面笔记本 + 手机的混合编队）。
- 距离：交火距离最远 10 米。
- 硬件：每名玩家一台手机（Android / iOS），具备可用摄像头。
- 网络：所有设备处于同一局域网（同一个 Wi-Fi 或其中一台电脑开热点）；**不需要互联网**。
- 组织方式：一名玩家在桌面电脑上创建房间，其他人（桌面 + 手机）通过房主地址和 4 位房间号加入。
- 典型一局：默认 5 分钟、10 杀上限。

### 1.4 设计原则

1. **本地优先**：不登录、不依赖云数据库、不依赖互联网；断网也能玩（局域网除外）。
2. **宁可未识别，不可扣错人**：识别不确定时按未命中处理，不猜测目标。
3. **低门槛**：不需要额外硬件；用手机浏览器打开即可，无需安装 App Store 应用。
4. **手机操作直觉**：虚拟扳机在右下角（拇指自然位置），目标选择在左侧滑动。
5. **性能优先**：手机 GPU 能力有限，AI 识别和 3D 渲染需做针对性优化。

## 2. 整体页面框架与导航结构

### 2.1 页面清单

| 页面 | 作用 |
| --- | --- |
| 启动加载页 | 读取 IndexedDB 本地数据、检查摄像头/识别引擎，显示加载状态 |
| 首页/总览 | 玩家信息、模式入口、战绩总览（桌面版首页的精简版） |
| 房间入口 | 输入房主地址 + 房间号加入（无创建房间，手机端不跑服务器） |
| 房间大厅 | 红蓝分队、玩家准备、建档状态、查看比赛设置 |
| 建档弹窗 | 用摄像头采集正面/背面的人脸和衣着 |
| 战斗页 | 摄像头画面 + AR 手臂/枪 + 准心 + HUD + 触屏输入 |
| 结算页 | 胜负、比分、个人战绩 |
| 设置弹窗 | 音量、识别质量、摄像头选择 |
| 战绩弹窗 | 查看本机保存的历史比赛 |

### 2.2 导航结构

```
启动加载
└─ 首页/总览
   ├─ 团战
   │  └─ 房间入口（仅加入，无创建）
   │     └─ 房间大厅
   │           └─ 建档弹窗
   │           └─ 开始比赛 → 战斗页 → 结算页
   │                 └─ 离开房间 → 首页
   ├─ 战绩（弹窗）
   └─ 设置（弹窗）
```

### 2.3 与桌面版的差异

| 功能 | 桌面版 | 移动版 | 说明 |
| --- | --- | --- | --- |
| 创建房间 | ✅ | ❌ | 手机端不跑 LanServer |
| 加入房间 | ✅ | ✅ | 输入 IP:端口 + 房间号 |
| 建档 | ✅ | ✅ | 摄像头采集流程相同 |
| 战斗页 | 键盘/鼠标 | 触屏（虚拟扳机 + 滑动选目标） | 交互方式不同 |
| 本地存储 | Electron IPC → JSON 文件 | IndexedDB | 存储机制不同 |
| 备份导出/导入 | ✅ 文件对话框 | ❌ | 移动端文件系统受限 |
| Field Test 日志 | ✅ JSONL 文件写入 | ❌ | 桌面专属 |
| 调试信息面板 | ✅ | ❌ | 开发调试用 |
| 战绩保存 | ✅ | ✅ | 相同 |
| 设置 | 音量/质量/摄像头/备份/清除 | 音量/质量/摄像头 | 精简 |
| PWA 安装 | ❌ | ✅ | manifest.json + service worker |

## 3. 本地数据与存储

### 3.1 存储方式

移动端使用 **IndexedDB** 替代桌面版的 Electron IPC + JSON 文件存储。

| 数据 | IndexedDB 对象存储 | 说明 |
| --- | --- | --- |
| `profile` | `profile` store | 玩家本地身份与昵称 |
| `settings` | `settings` store | 音量、识别质量、摄像头选择 |
| `appearance` | `appearance` store | 人脸特征、衣着特征（不存缩略图） |
| `history` | `history` store | 历史比赛记录 |

### 3.2 数据保留要求

以下数据必须在关闭浏览器标签页、重启手机后仍然存在：

- 玩家昵称和个人标识。
- 音量、识别质量、摄像头选择等设置。
- 人脸/衣着建档数据。
- 历史比赛记录。

以下数据只存在于内存中，不要求跨重启保留：

- 当前房间、队伍、准备状态。
- 正在进行中的比赛状态（血量、比分、计时）。

### 3.3 隐私要求

- 原始人脸照片不保存。
- 房间内只同步识别特征（人脸特征向量、衣着特征），不同步原始照片。
- 不采集、不上传与游戏无关的个人信息。

## 4. 第一版必须完成的功能

### 4.1 应用与首页

- [ ] 在手机浏览器中打开 URL 后，10 秒内显示首页。
- [ ] 首页具备：玩家信息、团战入口、战绩入口、设置入口。
- [ ] 显示本地玩家昵称，可修改并持久化到 IndexedDB。
- [ ] 显示总场次、击杀、死亡、命中率、胜率等汇总数据（来自本机历史记录）。
- [ ] 设置弹窗、战绩弹窗可正常打开和关闭。

### 4.2 房间与组队

- [ ] 输入房主地址（如 `192.168.1.20:17890`）和 4 位房间号后成功加入。
- [ ] 加入后进入房间大厅，看到所有玩家列表。
- [ ] 玩家可自行选择红队或蓝队；队伍满员后不可加入。
- [ ] 昵称、队伍、准备状态、建档状态在大厅实时同步。
- [ ] 可查看房主设置的比赛时长和击杀上限（只读）。
- [ ] 非房主玩家可切换"已准备/未准备"。
- [ ] 所有玩家准备/建档完成、房主开始后进入 3 秒倒计时。
- [ ] 连接失败时给出明确提示（地址错误、房间号错误、房间已满、防火墙/局域网问题）。

### 4.3 赛前建档与识别

- [ ] 每位玩家可在手机上打开摄像头完成建档。
- [ ] 至少采集正面和背面两个视角。
- [ ] 采集时提取人脸特征和衣着特征。
- [ ] 没有检测到人体时提示"没有检测到人体"。
- [ ] 建档数据保存到本机 IndexedDB，并通过房间同步给其他玩家。
- [ ] 识别时优先人脸，人脸不可用时使用衣着；两者都不确定时显示"目标未识别"。
- [ ] 识别结果在准心附近显示昵称和队伍颜色。
- [ ] **不得把命中判给错误玩家**；无法确定时按未命中处理。

### 4.4 战斗画面（AR 表现）

- [ ] 全屏实时摄像头画面，画面不镜像。
- [ ] 屏幕底部显示 3D 手臂和所持枪械。
- [ ] 枪口指向与屏幕中心准心一致。
- [ ] 待机时有轻微呼吸/晃动；开火时有后坐力动画。
- [ ] 开火时枪口出现火花/闪光，并播放枪声。
- [ ] HUD 显示：比分、倒计时、自己的血量、击杀信息、锁定目标提示。
- [ ] 阵亡时显示阵亡状态和复活倒计时；受击时有视觉提示。

### 4.5 触屏输入

- [ ] **虚拟扳机**：屏幕右下角有一个半透明按钮，按下即开火。
- [ ] **目标选择**：屏幕左侧有一个可滑动的目标选择面板，手指上下滑动选择要瞄准的玩家，松开确认。
- [ ] 开火时自动使用当前选中的目标（若未选择则按未命中处理）。
- [ ] 触屏操作不遮挡 HUD 核心信息（比分、血量、准心）。
- [ ] 支持横屏模式：扳机在右下角，目标选择在左下侧。

### 4.6 射击与命中判定

- [ ] 点击虚拟扳机开火。
- [ ] 开火后在准心附近分析画面，判断是否有人、是谁、属于哪队。
- [ ] 命中敌人：每枪 25 血，满血 100，4 枪击倒。
- [ ] 命中队友：不扣血，显示"队友 · 未造成伤害"提示。
- [ ] 未识别到目标：按未命中处理，显示"目标未识别"。
- [ ] 目标已阵亡、刚复活处于无敌、或已断线：本次射击不造成伤害。
- [ ] 准心附近有多人时，优先选择离准心最近、识别最确定的目标。

### 4.7 比赛规则

- [ ] 比赛时长：3~10 分钟，默认 5 分钟（由房主设置，手机端只读）。
- [ ] 击杀上限：10~30 杀，默认 10 杀（由房主设置，手机端只读）。
- [ ] 任一条件先满足即结束：某队先达到击杀上限直接获胜；时间到则比较双方击杀数。
- [ ] 血量归零：阵亡，5 秒后满血复活；复活后 2 秒无敌。
- [ ] 阵亡期间不能开火；复活后可以继续。
- [ ] 比赛结束显示胜方、比分、个人击杀/死亡/命中率。
- [ ] 结算数据保存到本机 IndexedDB 历史记录。

### 4.8 联机

- [ ] 仅使用局域网，不需要互联网。
- [ ] 同步内容：玩家列表、队伍、准备状态、建档特征、血量、比分、击杀、比赛阶段。
- [ ] 不同步摄像头画面，不传输原始照片。
- [ ] 断线/退出有基本处理：玩家离开后从房间移除或标记为不可用；房主离开则房间关闭。
- [ ] 至少支持 2 台设备同时联机（桌面 + 手机）。

### 4.9 设置

- [ ] 音量调节。
- [ ] 识别质量：性能/均衡/精准。
- [ ] 摄像头设备选择（前摄/后摄）。
- [ ] 清除本地数据（二次确认）。

### 4.10 PWA

- [ ] 提供 `manifest.json`，可在手机浏览器中选择"添加到主屏幕"。
- [ ] 添加到主屏后以独立窗口启动，隐藏浏览器地址栏。
- [ ] Service Worker 缓存核心资源，支持离线访问首页（不缓存战斗页）。
- [ ] 提供各尺寸应用图标。

## 6. 验收标准

> 验收环境：桌面电脑 1 台（运行桌面版房主）、手机 1~2 台，同一局域网，室内正常照明。
> 关键原则：识别不确定时必须按未命中处理；任何情况下不得把伤害扣给错误玩家。

### 6.1 启动与首页

- [ ] 手机浏览器打开 URL 后，10 秒内显示首页。
- [ ] 首页布局适配手机竖屏；所有按钮可点击。
- [ ] "团战"可点击进入房间入口。
- [ ] 修改昵称后关闭浏览器标签并重新打开，昵称仍然是修改后的值。

### 6.2 本地数据与持久化

- [ ] 首次打开后，IndexedDB 中生成 profile、settings、history 记录。
- [ ] 修改音量、识别质量、摄像头选择，关闭并重新打开后设置保持。
- [ ] 完成建档后关闭浏览器并重新打开，建档状态和特征仍然存在。
- [ ] 完成一局比赛后重新打开应用，战绩弹窗中仍能看到该场比赛。

### 6.3 加入房间

- [ ] 输入正确的房主地址和房间号后成功进入同一大厅。
- [ ] 输入错误房间号 → 提示"房间号不正确"。
- [ ] 输入错误地址/房主未开房 → 提示连接失败。
- [ ] 房间已满 → 提示"房间已满"。
- [ ] 队伍满员 → 提示"该队已满"。

### 6.4 建档与识别

- [ ] 打开建档弹窗后能看到实时摄像头画面。
- [ ] 正面采集成功，显示采集成功状态；背面采集成功。
- [ ] 没有检测到人体时，提示"没有检测到人体"。
- [ ] 完成建档后，大厅中自己的状态显示"已建档"。
- [ ] 重新打开应用后无需重新建档。

### 6.5 战斗画面

- [ ] 进入战斗后 3 秒内出现摄像头画面、手臂/枪械和准心。
- [ ] 准心固定在屏幕中心。
- [ ] 开火时可见枪口火花/闪光，能听到枪声，枪械有后坐力动画。
- [ ] HUD 正常显示比分、倒计时、血量和击杀信息。
- [ ] 阵亡后显示倒计时，5 秒内不能开火；复活后恢复。

### 6.6 触屏输入

- [ ] 点击虚拟扳机（右下角）能成功开火。
- [ ] 在左侧滑动选择目标后，开火使用选中的目标。
- [ ] 触屏操作不遮挡准心和核心 HUD。
- [ ] 横屏模式下布局正确。

### 6.7 命中与伤害

- [ ] 命中敌人一次扣除 25 血；4 次命中后对方阵亡。
- [ ] 命中队友不扣血，并出现提示。
- [ ] 准心附近无人时按未命中处理。
- [ ] 目标处于 2 秒复活无敌时，射击不扣血。
- [ ] 桌面和手机上的血量、比分、击杀信息在 1 秒内同步。

### 6.8 比赛规则

- [ ] 默认 5 分钟 / 10 杀。
- [ ] 时间耗尽或达到击杀上限时比赛结束。
- [ ] 阵亡 5 秒后复活；复活后 2 秒内被射击不掉血。
- [ ] 结算页数据与服务端一致。
- [ ] 返回大厅后数据重置，可重新准备。

### 6.9 联机与异常

- [ ] 桌面房主 + 手机队员同时进行一局，双方画面中的血量/比分/击杀一致。
- [ ] 手机关闭浏览器/断网后，桌面能看到其状态变化。
- [ ] 房主关闭房间后，手机收到断开提示并回到首页。

### 6.10 性能

- [ ] 手机战斗过程中摄像头画面和枪械动画持续更新，不出现超过 2 秒的界面卡死。
- [ ] 识别引擎在手机"均衡"质量下持续运行，手机不出现明显发热降频。
- [ ] 连续进行 2 局比赛，浏览器标签不崩溃。

### 6.11 PWA

- [ ] 手机浏览器中可看到"添加到主屏幕"提示。
- [ ] 添加到主屏后以独立窗口启动，无浏览器地址栏。
- [ ] 离线打开首页正常（不缓存战斗页）。

## 附录 B：技术假设与风险

1. **手机 AI 识别性能**：`@vladmandic/human` 在桌面 Chrome 上需要 200–340ms/帧，手机端 GPU/WASM 性能可能不足。V1 需要实测手机上的帧率，必要时降低检测分辨率和频率，或换用 MediaPipe。
2. **手机摄像头差异**：不同手机摄像头分辨率、视场角、低光表现差异大。V1 需要提供摄像头选择，并在设置中展示实际分辨率。
3. **手机握持姿势**：捧手机时屏幕较小，HUD 元素需要精简布局。建议优先适配横屏模式。
4. **浏览器兼容性**：Chrome/Edge 支持较好，Safari 的 WebGL 和 IndexedDB 行为略有差异，需要额外测试。
5. **局域网与防火墙**：与桌面版相同，Windows 防火墙可能拦截房主端口。
6. **PWA 支持**：Chrome for Android 支持完整；Safari on iOS 支持部分 PWA 特性（无 service worker 推送，但可添加到主屏）。
7. **识别正确性**：与桌面版相同，10 米识别主要依赖衣着特征；逆光、暗光、衣服颜色过近会降低识别率。

## 附录 C：部署安全上下文补充（2026-10-24）

手机浏览器只在**安全来源**下允许摄像头和 Service Worker：

- `https://` 页面或 `localhost` 才能调用 `getUserMedia`；
- `https://` 页面不能连接明文 `ws://`，必须使用 `wss://`。

因此“手机直接访问 `http://电脑IP:端口`”在真机上不可用。V1 采用仓库自带的
独立代理进程（`scripts/lan-proxy.mjs`）：

```
手机 ──https/wss──> 代理 ──静态 dist/ + ws://127.0.0.1:17890──> 桌面 LanServer
```

证书使用 mkcert 生成，并在每台手机上安装一次根 CA。详见
`docs/LAN_DEPLOY.md`。该方案不修改桌面版仓库。
